hylon

An autonomous art agent that generates works from an artistic DNA, submits them to an independent AI jury, and publishes nothing without a human yes.

hylon is a harness, not an artist. It contains no opinions about what good art looks like. Everything it knows about taste lives in a single document — the artistic DNA — written by a human. The harness supplies the process: a generator that works inside the DNA, a jury that grades against it, an arithmetic gate that turns judgments into a verdict, and a final approval step that only a person can click. Both AI roles run through OpenRouter with one API key, so the models on either side of the table are a configuration choice, not a code change.

1 · The operational loop

On a schedule (or on demand), the daemon “wakes.” A wake is a bounded work session: it keeps producing candidates until one survives the jury, or until it runs out of time or money. Every candidate — whether it passes, fails, or gets stranded — is committed to git, so the repository is the complete, honest record of everything the machine ever made.

Three budgets keep the loop honest. A time budget (default 20 minutes per wake) stops open-ended tinkering. A cost fuse caps spending per wake and per day, measured from OpenRouter’s own per-call cost reporting, and is checked before each attempt — the agent never starts work it cannot afford to finish. And a turn limit bounds the generator’s internal loop. The budget is a fuse, not a target: hitting it means the machine goes back to sleep, not that it tries harder.

2 · The artistic DNA principle

The central design rule is a strict separation of powers: the harness owns the process; the DNA owns the taste. The DNA (identity/DNA.md) is a markdown document written by the artist that reads less like a biography and more like an operating system. It states who the artist is, the principles a work must enact (each with an ID the agents can cite), the lineage and references the practice answers to, the material constraints, and — critically — the validation rubric the jury will apply.

Both agents read the same document, but in different postures. The generator receives the DNA as its system prompt — an identity to inhabit — and is asked to produce work that would pass the DNA’s own rubric. The jury receives the DNA as a standard to apply, with explicit instructions not to be generous and a reminder that it did not make the work.

Why the separation matters. When the artist rejects a candidate with a note (“too reverent — I want more bite”), that note is appended to a guidance file the generator reads on future rounds. The jury never sees it. Feedback can steer what gets made, but it cannot quietly lower — or bend — the bar it is judged against. To change the bar, you edit the DNA itself.

The DNA also carries a catalogue of the artist’s existing works (seeded from identity/catalogue.seed.json and grown by the harness). It serves two purposes: it gives the generator a memory of what already exists, and it gives the jury the corpus for its duplicate check. hylon ships with a DNA template — the structure without the person — so a fresh clone becomes a different artist by filling in one file.

3 · The generator: an agent with a studio

The generator is not a single text completion. It is a small agent loop: the model is given three file tools — write_file, read_file, list_files — scoped to a private staging directory, and it works the way a person at a desk does: draft, read it back, notice the flaw, revise, and only then hand it in.

Every candidate must consist of exactly three files: the work itself (index.html), a written motivation connecting the piece to specific DNA principles and at least one named reference, and a machine-readable meta.json (title, summary, mechanism, principles, references, license). The motivation matters: it forces the generator to argue for the work in the DNA’s own terms, and it becomes part of the public record when the work is published.

One constraint is enforced by the harness rather than the DNA, because it is structural: the work must be fully self-contained. All CSS and JavaScript inline; no external requests of any kind — no CDNs, no web fonts, no fetch, no analytics. This is checked in layers: a fast pattern scan at generation time catches the obvious violations, and a restrictive Content-Security-Policy plus a sandboxed iframe at render time guarantees that anything the scan missed still cannot reach the network.

4 · The juror

The jury is a different model from a different vendor — a deliberate rule, so no model ever grades its own output. It receives the DNA, the catalogue digest, and the complete candidate (metadata, motivation, and full source code), and it returns one strictly structured JSON object: a boolean for each hard gate, an integer score for each criterion, the references and principles it recognized, a short rationale, and optionally reservations and a revision suggestion.

What the jury does not return is a verdict. It is explicitly told not to compute totals. The division of labor is precise:

The model suppliesThe harness computes
Judgments: gate booleans, 0–5 scores, rationale, reservations Arithmetic and the decision: weighting, thresholds, the verdict
Qualitative, model-dependent, non-deterministic Deterministic, unit-tested, identical for every model

This split exists because language models are unreliable accountants: a model asked to “add up the weighted scores and decide” will sometimes do the math wrong, or let the story it just told itself bend the outcome. In hylon, the gate is code. The model judges; the code decides. The full verdict is written to jury.json and committed alongside the work as a private record — it is never published to the public site.

5 · The scoring mechanism

Scoring happens in two stages, and the order is the point: gates first, points second. The rubric’s shape lives in agent.config.json; what each gate and criterion means lives in the DNA. The defaults ship with six gates and five weighted criteria.

The two-stage design encodes a specific belief about quality: some failures are not compensable. A gorgeous, witty, technically perfect work that violates a hard gate — say, it’s a duplicate, or it drops the required license — scores zero consideration. Points cannot buy back a gate. Above the gates, the weights say what the practice values most: in the default rubric, novelty and nuance together account for 60% of the possible total, while craft is worth the least — a deliberate hedge against rewarding polish over ideas.

The thresholds are tunable and honest about uncertainty. A strong work (≥ 38/50 with all gates passed) and a borderline one (30–37) both reach the human; the difference is framing, since the borderline verdict carries the jury’s specific reservations. Below 30, the machine doesn’t bother the artist at all — it archives the work and tries again.

6 · The human gate

Nothing hylon makes becomes public on its own authority. When a candidate survives the jury, it lands in workspace/pending/ and the artist is notified with a link to a local dashboard, which renders the work in a sandboxed iframe next to its motivation and the jury’s verdict. From there, the artist has three moves:

  • Approve — the only action in the entire system that writes to published/, from which the public site is assembled (minus the private jury.json).
  • Reject, optionally with a note — the work is archived; the note joins the guidance file the generator reads next round.
  • Refine — the artist writes feedback and the generator reworks the piece in place, re-submits to the jury, and waits at the gate again. A directed refinement is never auto-rejected: you asked for it, so you get to see it.

There is also a recovery path for accidents: if a work is fully generated but the jury call fails, the finished piece is never deleted. It is parked in orphaned/ — paid for, complete, and recoverable — where the dashboard can send it back through the jury with one click.

7 · Why this shape

The architecture keeps four promises, and everything above serves one of them:

  • The hard gate is sacred. The autonomous loop is write-only to pending/ and rejected/; publication requires a person.
  • No model grades its own work. Generator and jury are different vendors, and the verdict arithmetic belongs to neither.
  • Taste is legible and versioned. The DNA is a text file in git. When the bar changes, there is a diff.
  • Spending is bounded by design. Time budget, dollar fuse, turn limit — checked before work starts, not after it runs away.
